# Project Report
## AI-Powered Hospital Workforce & Patient Flow Management System

### Abstract
Hospitals may experience fluctuating patient arrivals, uneven department workloads, waiting-time pressure and staffing challenges. This project presents an academic analytics prototype that explores patient-volume forecasting and draft staff shift allocation. The application uses Python, Streamlit, SQLite, Pandas, Plotly and a Random Forest regression model. Synthetic historical data is used to demonstrate the workflow without exposing real patient information.

### 1. Introduction
Patient flow and workforce planning are important operational activities. A data-driven view of historical demand can help administrators understand patterns and prepare staffing plans.

### 2. Problem Statement
Manual planning may not consistently account for day-of-week patterns, department-level demand and changing workloads. The proposed prototype combines descriptive analytics, forecasting and draft scheduling in one interface.

### 3. Objectives
- Analyze patient volumes and waiting-time patterns.
- Forecast patient counts for a short future horizon.
- Estimate staffing demand using configurable role requirements.
- Allocate available staff into draft shifts.
- Present insights through interactive dashboards.

### 4. Existing System
In a basic manual workflow, patient counts and staff rosters may be maintained separately in spreadsheets. This can make consolidated analysis and scenario planning difficult.

### 5. Proposed System
The proposed system includes an overview dashboard, patient analytics, a Random Forest forecast module, a staff directory, shift allocation and CSV data exchange.

### 6. System Architecture
Data CSV / Synthetic Generator → Validation & Pandas Processing → SQLite Database → Forecast Model / Scheduling Logic → Streamlit Dashboard & Reports.

### 7. Methodology
Synthetic daily patient counts are generated by department with calendar and random variation. Calendar features (weekday, month, day-of-year, weekend indicator) and department encoding are used by a Random Forest regressor. A chronological holdout split is used for validation. MAE and RMSE are displayed as error measures. The scheduler allocates available staff by department and role against user-entered requirements and reports shortages.

### 8. Implementation
The application is divided into data generation, database access, forecasting, scheduling and Streamlit presentation modules. Users can inspect patient trends, train forecasts, add staff, upload CSVs and generate draft schedules.

### 9. Results and Discussion
The system demonstrates an end-to-end workflow using synthetic data. The forecast charts show model-generated estimates for future dates. The schedule table shows assigned staff and any unmet demand. Results are illustrative and depend on the generated dataset and configured requirements.

### 10. Testing
Core tests verify that the forecasting function returns non-negative predictions for the requested horizon and that the scheduler does not assign the same employee to the same shift more than once in a generated schedule.

### 11. Limitations
The synthetic dataset is not representative of a real hospital. The forecasting model is a baseline demonstration. The scheduler is a greedy heuristic and does not encode all real-world constraints such as credentialing, statutory rest periods, overtime rules, leave, fairness over multiple weeks or emergency coverage.

### 12. Future Scope
- Evaluate with approved, anonymized hospital data.
- Add role qualifications, leave and weekly rest constraints.
- Compare forecasting algorithms and tune hyperparameters.
- Add user authentication, audit logs and role-based access.
- Integrate secure hospital information systems after privacy and security review.

### 13. Conclusion
The prototype demonstrates how analytics and machine learning can support exploratory patient-flow forecasting and draft workforce planning. It is suitable for academic demonstration and requires domain validation before operational use.
